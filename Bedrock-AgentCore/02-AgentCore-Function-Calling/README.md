# Function Calling with Amazon Bedrock

This demo implements **WanderBot**, a travel assistant that uses function
calling through the Strands Agents SDK and Amazon Bedrock. Rather than guessing
about travel details, the model can select tools, provide their arguments, and
use the returned data to answer the user.

## How function calling works in this demo

1. The AgentCore app receives a request containing a `message`.
2. The code creates a Strands `Agent` with the Nova 2 Lite Bedrock model, the
   travel-assistant system prompt, and three tools.
3. The model decides whether a tool is relevant. For flight or hotel requests,
   the system prompt instructs it to use the matching search tool.
4. Strands calls the selected tool with arguments generated by the model.
   Custom tools read the local JSON datasets, filter and format their results,
   then return those results to the agent.
5. The agent uses the tool result to produce its response. The app returns that
   response to the caller.

Tool calling is orchestrated by the agent; the model does not directly read the
JSON files. The custom tools are registered with the `@tool` decorator, and
their docstrings describe when to use them, their arguments, and their results.

## Available tools

| Tool | Arguments | Behavior |
| --- | --- | --- |
| `current_time` | None | Built-in Strands tool that provides the current date and time. |
| `search_flights` | `origin`, `destination`, `date` | Searches by IATA airport codes and exact `YYYY-MM-DD` date. Matching is case-insensitive for airport codes. Results include flight times, status, price, seats, gate, and aircraft. |
| `search_hotels` | `city`, optional `max_price_usd` (default `999.0`) | Searches case-insensitively by city, includes only available properties at or below the nightly price limit, and sorts results from least to most expensive. Results include rating, room types, amenities, check-in, and cancellation details. |

The flight and hotel data are static sample records in `datasets/`; they are
not live inventory. A search with no matching records returns a helpful
no-results message.

## Requirements

- Python with the packages listed in `requirements.txt`
- AWS credentials available to the process
- Access to the `us.amazon.nova-2-lite-v1:0` model in the configured AWS region
- The Bedrock AgentCore SDK runtime for running the app

## Install and verify the AgentCore CLI

Before continuing, install `uv` and the AgentCore starter toolkit:

```bash
pip install uv
uv pip install bedrock-agentcore-starter-toolkit
```

Verify that the AgentCore CLI is available:

```bash
agentcore --help
```

## Run and test locally

From this directory, configure the AgentCore project and start the local development server:

```bash
agentcore configure
agentcore dev
```

Leave `agentcore dev` running. In a second terminal, run a local test invocation:

```bash
agentcore invoke --dev '{"message": "Find flights from LHR to CDG on 2026-03-15"}'
```

## Deploy and verify

Once local tests pass, deploy the application:

```bash
agentcore deploy --auto-update-on-conflict
```

Then verify the deployed application with an invocation:

```bash
agentcore invoke '{"message": "Find a hotel in Barcelona for under $200 per night"}'
```



## Dataset filename note

`search_flights` reads `datasets/flights.json`, but the file currently present
in this folder is named `datasets/filghts.json`. Rename that file to
`flights.json` before using flight search; otherwise the flight tool raises a
file-not-found error. Hotel search reads `datasets/hotels.json`.
